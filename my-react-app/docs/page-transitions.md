# Destination page loaders

Services, Work (`/portfolio`), About and Contact display a named loader on entry. The loader uses the site's existing blue/white palette, editorial typography, page number, relevant icon and a brief description. It displays for 900ms, then fades out over 200ms. Reduced-motion preferences disable the movement and fade. The original Home startup loader is retained; returning Home does not replay it. Direct links to other pages use their destination loader without an extra startup loader.

The destination layout is not mounted until the loader finishes. No destination image element, including header artwork and content photography, exists during loading. Header artwork still starts its entrance on its own image load event, followed by the existing subtle float animation. Same-page clicks, search/state updates and Work filtering do not restart the loader. Route changes cancel previous timers, and unmounting or finishing the loader releases its scroll lock. Contact inquiry state remains with the router location.

Validation: build and ESLint pass. React DOM checks in JSDOM under StrictMode verify the loader at 899ms, exit at 900ms, destination/images still absent at 1099ms, and content mounting at 1100ms. They also check image-load readiness, named destinations, Work filtering, Contact subject prefill, same-page navigation, rapid history changes cancelling stale timers, Home return/startup behavior, and cleanup. These checks now live in `tests/website.test.mjs` and run through `npm run check`, with JSDOM as a development dependency. Browser appearance and animation timing remain visually unverified because no browser connection is available.
